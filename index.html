The method

K-Means is an unsupervised method: it receives no correct answers and groups points by distance alone. The example below uses the exam scores from class with K = 3 and starting centers 30, 61 and 92.

  1. Choose K

    K is the number of clusters. The analyst sets it before the algorithm runs; K-Means does not determine it.

  2. Place K starting centers

    A center is a location. It begins at a data point in this lab, and after the first update it is usually not one. k-means++, the scikit-learn default, chooses starting points that tend to lie far apart.

  3. Assign each point to the nearest center

    Compute the distance from the point to every center and keep the smallest.

    d(p, c) = √[ (xp − xc)² + (yp − yc)² ]

    Example. Student A scored 58. The distances to 30, 61 and 92 are 28, 3 and 34, so A joins the center at 61.

  4. Move each center to the mean of its points

    Average each feature separately over the points in the cluster.

    cj = (1 / nj) Σi in cluster j xi

    Example. Students B, D, G and J scored 30, 32, 42 and 45. Their mean is 149 / 4 = 37.25, so that center moves to 37.25.

  5. Repeat until no point changes cluster

    Once memberships stop changing, the centers stop moving as well. In this example the final centers are 37.25, 59.33 and 89.33.

What K-Means minimizes

The objective is inertia, also called the within-cluster sum of squares or SSE: the squared distance from each point to its own center, added over all points. Lower inertia means tighter clusters.

inertia = Σj Σi in cluster j ‖xi − cj‖²

Assignment cannot raise inertia, because each point moves only to a center at least as close. Update cannot raise it either, because the mean is the location with the smallest total squared distance to the cluster's points. There are finitely many possible groupings, so the algorithm must stop. It may stop at a local minimum rather than the best possible grouping, which is why the start matters.

k-means++: choosing better starting centers

Because a poor start can trap the algorithm in a poor result, k-means++ spreads the starting centers apart while keeping the choice random.

  1. Choose the first center uniformly at random from the data.
  2. For each point, compute D(x)², its squared distance to the nearest center chosen so far.
  3. Choose the next center at random, with each point's chance proportional to D(x)².
  4. Repeat steps 2 and 3 until K centers are chosen, then run K-Means as usual.
P(x) = D(x)² / Σall points D(x)²

Example. Suppose the first center is student B, who scored 30. Student I scored 92, so D² = 62² = 3,844. Student D scored 32, so D² = 2² = 4. Over all ten students the D² values add to 13,539, so I is chosen next with probability 3,844 / 13,539 = 28.4%, and D with probability 4 / 13,539 = 0.03%.

Remark. Squaring the distance strengthens the preference for far-away points. The selection remains random, so k-means++ improves the start but does not guarantee the best result. Running it several times and keeping the lowest inertia helps further. scikit-learn's version also tries several candidates at each draw and keeps the most useful one.

To see each draw, set Starting centers to k-means++ in the lab.

The same run in scikit-learn

from sklearn.cluster import KMeans
import numpy as np

scores = np.array([58, 30, 59, 32, 61, 86, 42, 90, 92, 45]).reshape(-1, 1)
start = np.array([[30], [61], [92]])

model = KMeans(n_clusters=3, init=start, n_init=1).fit(scores)
print(model.cluster_centers_.ravel())   # final centers
print(model.labels_)                    # cluster of each student
print(model.inertia_)                   # inertia

By default, scikit-learn uses k-means++ and keeps the best of its runs. The fixed init above reproduces a single run from this lab.

How DBSCAN works

DBSCAN defines a cluster as a dense region of points. It needs two settings: eps, the radius of a neighborhood, and min_samples, the number of points that make a neighborhood dense. In scikit-learn the count includes the point itself. Every point then takes one of three roles.

  • Core point: at least min_samples points lie within eps of it.
  • Border point: not a core point, but within eps of a core point.
  • Noise: neither of these, so it joins no cluster.

Core points within eps of each other join the same cluster, and each border point joins a cluster of a nearby core point. The number of clusters follows from the data.

Example. On the exam scores with eps = 5 and min_samples = 3, student H (90) has 86, 90 and 92 within 5 points, so H is a core point. Student F (86) has only 86 and 90 within 5, but 90 is a core point, so F is a border point. Student B (30) has only 30 and 32 within 5 and neither is a core point, so B is noise. The result is two clusters, {A, C, E} and {F, H, I}, with B, D, G and J left as noise.

Remark. Neither method is better in general. On the moons, K-Means scores an ARI of 0.26 and DBSCAN 1.00. On the touching groups, K-Means scores 0.90 and the best of 1,121 DBSCAN settings tried scores 0.67. ARI requires known groups, which real clustering problems usually do not have. DBSCAN relies on distances, so features should be on comparable scales.

The same comparison in scikit-learn

from sklearn.cluster import KMeans, DBSCAN
from sklearn.datasets import make_moons
from sklearn.metrics import adjusted_rand_score

X, y = make_moons(n_samples=200, noise=0.05, random_state=0)

km = KMeans(n_clusters=2, n_init=10, random_state=0).fit_predict(X)
db = DBSCAN(eps=0.3, min_samples=5).fit_predict(X)   # -1 means noise

print(adjusted_rand_score(y, km))
print(adjusted_rand_score(y, db))

When K-Means fits

Suitable when

  • Features are numeric and on comparable scales
  • Clusters are compact and roughly round
  • Every observation should belong to a cluster
  • A fast method for large data is needed

Use caution when

  • Outliers can pull a mean away from its group
  • Clusters are curved, nested or very unequal in size
  • Noise points should stay unassigned; DBSCAN allows this
  • The number of clusters is unknown and hard to judge
